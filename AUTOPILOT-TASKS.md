# Tasks: Robustness review of autopilot-loop

Bash 4.4+ in the existing style: short functions, English comments and messages, `g` instead of plain `git`, no new dependencies, no renamed commands or config keys. Every fix gets at least one new check in `test/test_autopilot.sh` in the form `<condition> || fail "<what went wrong>"`, one per line. The number of `|| fail` checks is the test count, so existing checks must never be weakened, merged or deleted. Tests only use `test/fake-claude`. When a test simulates a missing tool, it uses a PATH made only of symlinks to the tools it needs (bash, git, jq, coreutils …), so the real `claude` can never be reached. `ROBUSTNESS.md`, `templates/` and `.github/` are not touched. Checked by a human: a real run on macOS (BSD tools, old `readlink`, the message under bash 3.2), full disk, machine reboot, and how the plugin behaves inside Claude Code.

- [x] 1. [errors] `autopilot.sh` with a WORKDIR in autopilot.conf that does not exist exits non-zero with a message naming the missing path and "WORKDIR". Done when a test shows exit code ≠ 0, the output contains the path and "WORKDIR", and no line starts with "cd:" or contains "line [0-9]+:".
- [x] 2. [errors] `menu.sh status` when the task list file is missing prints a line naming the missing task list path and exits 0. Done when a test with the TASKS_FILE deleted shows exit 0, the output contains the path, and no output line starts with "grep:".
- [ ] 3. [errors] `menu.sh approve` when the ACCEPT_FILES do not exist exits non-zero, does not print "approved" and leaves `.autopilot/APPROVAL` byte-identical. Done when a test with a renamed acceptance file checks all three conditions (checksum of APPROVAL before == after).
- [ ] 4. [security] ACCEPT_FILES and LOCKED entries starting with `-` (e.g. `-accept.sh`) are treated as file names, not options (find, sha256sum, git). Done when a test project with `ACCEPT_FILES=(-accept.sh)` shows: `menu.sh approve` exits 0, `autopilot.sh` gets past the approval check, and a worker step that changes `-accept.sh` is rejected with "locked file changed".
- [ ] 5. [security] A run that adds a symlink in an allowed path pointing outside WORKDIR (absolute, or `../`) is rejected with a reason containing "symlink". A symlink pointing to a file inside WORKDIR stays allowed. Done when a test shows: outside link rejected, HEAD unchanged, link gone afterwards; inside link accepted.
- [ ] 6. [security] Changes inside a Git submodule of the work directory are rejected with a reason containing "submodule", and the submodule is restored afterwards. Done when a test with a local submodule (`git -c protocol.file.allow=always submodule add`) and a worker step that edits a file in it shows the rejection and that `git status --porcelain` in the work directory and in the submodule are empty afterwards.
- [ ] 7. [portability] The placeholders in the worker prompt (`{TEST_CMD}`, `{ACCEPT_CMD}`, `{TASKS_FILE}`, `{DECISIONS_FILE}`) are replaced literally, also when the value contains `&` (bash 5.2 `patsub_replacement`) or a backslash. Done when `test/fake-claude` saves the last worker prompt to `$FAKE_DIR/last-prompt` and a test with `TEST_CMD='bash check.sh && true'` finds the exact string `bash check.sh && true` in it.
- [ ] 8. [portability] Shortening task text for history.log, BLOCKED.md and the commit message never cuts a multibyte character (umlauts). Done when a test with a task made of umlauts across the cut columns (e.g. 60 × "ü"), run under `LC_ALL=C.UTF-8`, shows that history.log, BLOCKED.md and `git log -1 --format=%B` all pass `iconv -f UTF-8 -t UTF-8` without error.
- [ ] 9. [fresh] `autopilot.sh` checks before the first run that Git can commit in the work directory (e.g. `g var GIT_COMMITTER_IDENT`). Without an identity it stops with a message containing "user.email" and "git config". Done when a test with `user.useConfigOnly=true`, no user.* settings and `GIT_CONFIG_GLOBAL=/dev/null` shows exit code ≠ 0, that message, and that fake-claude was never called (no `$FAKE_DIR/step-nr`).
- [ ] 10. [fresh] `plan accept` in a repository with a detached HEAD writes the commit hash as BASE_BRANCH instead of "main". Done when a test after `git checkout --detach` shows that BASE_BRANCH in the generated autopilot.conf equals `git rev-parse HEAD` of the original, and `menu.sh result` exits 0 without a line containing "fatal:".
- [ ] 11. [fresh] `plan` + `plan accept` work for a plan file in a nested sub-folder (`docs/spec/plan.md`) of a repo whose default branch is `trunk` and whose path contains a space, `$` and "ü". Done when a test checks that sourcing the conf in a subshell gives BASE_BRANCH=trunk, LOCKED=(docs/spec/plan.md), PLAN_FILE equal to the absolute plan path and WORKDIR equal to the created worktree, and that `menu.sh status` exits 0 and shows the plan path.
- [ ] 12. [fresh] Running `plan <file>` and `plan accept` a second time for the same project succeeds. The existing worktree and the `autopilot` branch are reused. Done when a test runs both twice in a row and shows exit 0 both times, `standard.conf` points to the project's autopilot.conf, and the `trusted` file contains exactly one line for that path.
- [ ] 13. [errors] When `plan accept` cannot create the work branch, the message includes the target path, Git's own reason (its last stderr line) and what to do. Done when a test with a regular file at `<repo>-autopilot` shows exit code ≠ 0 and a message containing that path and the word "move" or "remove".
- [ ] 14. [errors] With a config directory that cannot be written to, `menu.sh plan <file>` and `menu.sh trust` exit non-zero with a message naming the directory and "XDG_CONFIG_HOME". Done when a test with `XDG_CONFIG_HOME` in a `chmod 555` folder (skipped when `id -u` is 0) shows both exit codes ≠ 0, both messages, and no output line starting with "mkdir:".
- [ ] 15. [errors] When `claude` is not on PATH, `menu.sh plan <file>` and `autopilot.sh` exit before any other work with a message containing "claude" and "not found" plus the installation hint. Done when a test with a restricted symlink PATH (without claude) shows: both exit codes ≠ 0, the message, no `.autopilot/draft` folder, and no "Run 1" in history.log.
- [ ] 16. [crash] When Claude reports an error that is not a usage limit (`is_error: true`, e.g. "Invalid API key · Please run /login" or "API Error: Connection error"), `autopilot.sh` stops right away instead of counting rejections. Done when `test/fake-claude` returns such an answer with exit 1 if `$FAKE_DIR/error.txt` exists, and a test shows: exit code ≠ 0 after one run, history.log contains the error text, grades.csv unchanged, `git status --porcelain` empty, HEAD unchanged.
- [ ] 17. [crash] `menu.sh plan <file>` with invalid JSON or empty output from Claude exits non-zero with a message saying that Claude gave no usable answer, plus the path of the answer file. Done when `test/fake-claude` returns raw text or nothing for the setup prompt if `$FAKE_DIR/garbage` exists, and a test checks both cases: exit code ≠ 0, that message, and no output line starting with "jq:" or "parse error".
- [ ] 18. [crash] A reviewer run that hits the time limit (exit code 124) is rejected with a reason containing "time limit" instead of "no verdict". Done when `test/fake-claude` sleeps for `$(cat $FAKE_DIR/review-sleep)` seconds on reviewer prompts, and a test with `CLAUDE_TIMEOUT=2` and a 5-second sleep finds "time limit" in history.log and finishes within 30 seconds.
- [ ] 19. [crash] SIGTERM or SIGINT during a worker run ends `autopilot.sh` cleanly: the child process is killed, the work directory is reset to the last commit, and history.log notes "Interrupted" with the hint "autopilot start". Done when a test starts autopilot.sh in the background with a step that writes a file and then sleeps 30 seconds, sends TERM after the file appears, and checks: the process ends within 5 seconds, HEAD unchanged, `git status --porcelain` empty, the history line present.
- [ ] 20. [crash] A leftover `.autopilot/WAITING` with no run active (after a crash or reboot) no longer shows as waiting. Done when a test with WAITING present and no run shows: `menu.sh status` does not contain "WAITING for your OK", `menu.sh status --short` is empty, and `menu.sh continue` prints "Nothing is waiting".
- [ ] 21. [concurrency] `autopilot.sh` takes a lock per project in `.autopilot/` (mkdir plus PID file, no flock). A second instance exits non-zero with "already running" and does not change the first run's state. A lock whose PID is dead is taken over. Done when a test shows: the second instance during a supervised wait exits ≠ 0 within 5 seconds, WAITING still exists, the first run finishes after `continue`; and with a lock holding a dead PID, autopilot.sh starts normally.
- [ ] 22. [concurrency] Two projects with the same NAME in different folders get different tmux session names. Done when a test with a fake `tmux` (in a separate PATH folder, logging its arguments) runs `menu.sh status` for both projects and finds two different `-t` values in the log.
- [ ] 23. [portability] `menu.sh start 1` without tmux on PATH exits non-zero with a message containing "tmux" and the installation hint, and does not print "Started". Done when a test with a restricted symlink PATH (no tmux, no claude) checks exit code, message and the missing "Started".
- [ ] 24. [portability] `autopilot.sh` without jq on PATH stops before the first run with a message containing "jq". Done when a test with a restricted symlink PATH (no jq, fake-claude only by explicit path) shows exit code ≠ 0, the message, and no "Run 1" in history.log.
- [ ] 25. [portability] `menu.sh report` works without python3, and `menu.sh chart` prints a clear message instead of "command not found". Done when a test with a restricted symlink PATH (no python3) shows: report output contains the text from `$FAKE_DIR/report.txt`, chart exits ≠ 0 with a message containing "python3", and no output line contains "command not found".
- [ ] 26. [security] Task text containing `$(touch <file>)`, backticks, `;` and a leading `-e` is never executed and appears literally in history.log and the commit message. Done when a test with such a task, worked through by a fake step, shows: the marker file does not exist, and history.log and `git log -1 --format=%s` contain the literal text `$(touch`.
- [ ] 27. [plugin] `menu.sh status` gives the plugin a clear signal: with an untrusted conf exit code 4 and output containing "autopilot trust", without any project exit code 3 and output containing "autopilot plan", and in neither case does it start with "Status:". `hooks/register.ts` then shows the trust message instead of offering "New project from file". Done when a test checks both exit codes and messages for `menu.sh status` and `menu.sh status --short` (the TypeScript part is checked by a human).
